# 차트도감 — 주식 차트 패턴 스크리너

코스피200·코스닥150·S&P 500 구성종목에서 유동성 상위 약 500종목을 추려
일봉을 쌓고, 널리 알려진 차트 패턴에 **지금 가장 가까운 종목**을 유사도 순으로
보여주는 모바일 웹앱. 서버 없이 정적 배포로 돌아간다.

패턴이 완성됐는지를 O/X로 찍지 않고 0~100점으로 근접도를 매긴다. 완성된
패턴은 이미 늦은 경우가 많고, 쓸모 있는 건 "80점짜리, 아직 진행 중인 것"이라서다.

각 패턴에는 **과거 성적표**가 붙는다. 승률은 기준선(아무 종목이나 아무 날
샀을 때)과 항상 나란히 표시한다 — 기준선 없는 승률은 아무 의미가 없기 때문이다.
기준선을 못 넘는 패턴도 그대로 표시한다.

## 가장 먼저 할 일

무료 소스가 지금 살아 있는지부터 확인한다. 30초면 끝나고, 여기서 1주차의
성패가 갈린다.

```bash
pip install -r requirements.txt
python collect.py --probe
```

기대 출력:

```
=== 소스 생존 점검 ===
  [OK]   KR 유니버스   350종목  ← pykrx
         예시: 삼성전자, SK하이닉스, LG에너지솔루션
  [OK]   KR 일봉 005930   14행  최종 2026-09-05  종가 XX,XXX  ← pykrx
  [OK]   US 유니버스   503종목  ← fdr
  [OK]   US 일봉 AAPL     14행  최종 2026-09-05  종가 XXX  ← fdr
```

`[FAIL]`이 뜨면 폴백이 작동했는지(`← seed` 등) 확인하고, 전부 실패했다면
아래 "소스가 막혔을 때"로.

## 수집

```bash
python collect.py --limit 20     # 먼저 20종목으로 감 잡기
python collect.py --market KR    # 국내만
python collect.py                # 전체 (첫 실행 10~20분)
```

산출물:

| 경로 | 내용 |
|---|---|
| `data/ohlcv/KR/005930.parquet` | 종목별 일봉 (증분 갱신) |
| `data/universe.parquet` | 확정 유니버스 + 유동성 지표 |
| `public/data/universe.json` | 프론트가 읽을 JSON |

두 번째 실행부터는 **마지막 저장일 이후만** 받는다. 매일 250일치를 500번
다시 받는 건 소스에 대한 민폐이자 차단당하는 지름길이라서.

## 구조

```
config.py            숫자는 전부 여기에만
sources/
  base.py            DataSource 인터페이스 + 공통 정규화
  pykrx_source.py    국내 1순위 (지수 구성종목 + 거래대금 직접 제공)
  fdr_source.py      국내·미국 겸용 + 번들 시드 리스트
  registry.py        폴백 체인, 소스별 성공/실패 집계
store.py             Parquet 증분 저장
universe.py          유동성 필터 (순수 함수, 테스트 대상)
collect.py           오케스트레이션
```

수집 코드가 아는 건 두 함수뿐이다.

```python
get_universe(market) -> DataFrame[code, name, market, source_index]
get_ohlcv(code, start, end) -> DataFrame[Date; Open High Low Close Volume Value]
```

나중에 KIS Open API나 유료 소스로 갈아탈 때 `DataSource`를 구현한 파일
하나만 새로 쓰고 `registry.default_registry()`의 순서에 끼우면 된다.
나머지 코드는 손대지 않는다.

## 유니버스 기준

| 시장 | 기준 | 목표 |
|---|---|---|
| 한국 | 코스피200 + 코스닥150 → 20일 평균 거래대금 30억 이상 | 약 250 |
| 미국 | S&P 500 → 20일 평균 거래대금 상위 | 약 250 |

공통 제외: 상장 이력 150일 미만, 최근 7일간 시세가 안 잡히는 종목.

필터마다 **몇 종목이 떨어졌는지 로그로 남는다**. 어느 날 유니버스가 갑자기
80종목이 되면 어느 필터가 잡아먹었는지 바로 보여야 하기 때문.

```
[KR] 유니버스 필터
   → 시작                          350
    - 이력 150일 미만                 4
    - 거래대금 30억 미만              62
    - 최근 7일 내 시세 없음            0
    - 거래대금 상위 250 밖            34
   → 최종                          250
```

넓히고 싶으면 `config.py`의 `KR_TOP_N` / `US_TOP_N`만 올린다. 다만 좁게
시작하는 데는 이유가 있다 — 하루 스캔 결과가 20~40개여야 **매일 눈으로 전부
검수할 수 있다**. 초기엔 코드가 맞는지 사람이 봐야 하는데, 결과가 300개면
아무도 안 본다.

## 안전장치

- **실패율 30% 초과 시 중단.** 소스가 막힌 날 멀쩡한 기존 캐시를 반쪽짜리
  데이터로 덮어쓰는 사고를 막는다.
- **개별 종목 실패는 캐시로 버틴다.** 어제까지 받아둔 값으로 유동성 지표를
  계산하고 넘어간다.
- **겹치는 구간은 새 값이 이긴다.** 소스가 과거 수치를 사후 정정하는 경우가
  있어서, 증분 수집 시 3~5일을 일부러 겹쳐 받는다.
- **`BRK.B` 같은 점 있는 티커**는 파일명에서 `-`로 바뀐다.

## 소스가 막혔을 때

무료 데이터는 "공짜라서" 문제가 아니라 **어느 날 갑자기 죽어서** 문제다.
순서대로 확인한다.

1. `python collect.py --probe` 로 어느 소스가 실패했는지 특정
2. 로컬에서는 되는데 GitHub Actions에서만 실패한다면 → 데이터센터 IP 차단.
   `runs-on`을 바꾸거나 셀프호스티드 러너를 검토
3. 국내가 막혔다면 → `pykrx` 대신 `fdr`이 받았는지 로그의 `←` 표시 확인
4. 미국이 막혔다면 → Alpha Vantage(무료 5회/분) 어댑터를 추가.
   `DataSource`만 구현하면 되고 30분이면 붙는다
5. 전부 막혔다면 → 유니버스는 `data/seed/sp500.csv` 번들로 버티고,
   시세는 전날 캐시로 서비스. 앱에 **데이터 기준일을 크게 표시**한다

## 웹으로 띄우기

빌드하면 `public/` 하나가 통째로 정적 웹사이트다. 서버가 필요 없다.

```bash
python scan.py            # 데모 데이터로 스캔 (실제 시세 없이도 됨)
python build_app.py       # public/index.html 생성
python3 -m http.server 8000 --directory public
```

`localhost:8000` 으로 열면 끝. **`index.html` 을 파일로 직접 열면 안 된다** —
브라우저가 `file://` 에서는 데이터 파일 읽기를 막기 때문에 오류 화면이 뜬다.
그럴 땐 화면이 이유와 해결 방법을 알려준다.

### 진짜 주소 만들기 (GitHub Pages, 무료)

1. GitHub에 리포지토리를 만들고 이 폴더를 푸시
2. 리포 **Settings → Pages → Source** 를 **GitHub Actions** 로 변경
3. **Actions → collect & deploy → Run workflow** 에서 `demo` 를 체크하고 실행

3분쯤 뒤 `https://<아이디>.github.io/<리포이름>/` 이 열린다. 실제 시세가
붙기 전에도 데모 데이터로 먼저 주소를 확인할 수 있게 해둔 것이다. 소스가
살아 있는 게 확인되면 `demo` 체크를 빼고 돌리면 실제 데이터로 바뀐다.

도메인을 붙이려면 Pages 설정의 Custom domain에 넣고 DNS만 맞추면 된다.

### 구조

| 파일 | 역할 |
|---|---|
| `public/index.html` | 앱 껍데기 (44KB). 데이터는 안 들어 있다 |
| `public/data/scan.json` | 스캔 결과. 배치가 매일 이것만 새로 쓴다 |
| `public/sw.js` | 서비스워커 — 껍데기는 캐시 우선, 데이터는 네트워크 우선 |
| `public/manifest.webmanifest` | 홈화면 설치 정보 |
| `public/icons/` | 앱 아이콘 |

데이터를 페이지에 박지 않고 따로 두는 이유는 단순하다. 매일 바뀌는 건
JSON뿐이라, 앱 페이지는 브라우저 캐시에 그대로 남아 있으면 된다.

### 폰에 설치하기

주소를 폰에서 열고 **공유 → 홈 화면에 추가**. 아이폰은 이 과정을 거쳐야
주소창 없는 전체화면으로 뜨고, 나중에 푸시 알림을 붙일 때도 홈화면 추가가
전제 조건이 된다(iOS 16.4 이상).

설치해두면 **지하철에서도 열린다.** 서비스워커가 마지막으로 받아둔 결과를
보여주고, 화면 상단의 데이터 기준일로 언제 것인지 알 수 있다.

## 자동화

`.github/workflows/collect.yml` 하나가 수집부터 배포까지 처리한다.

```
로직 검증 → 소스 점검 → 수집 → 스캔 → 빌드 → 데이터 커밋 → Pages 배포
```

평일 KST 18:00(국내 마감 후)과 KST 07:00(미국 마감 후)에 돌고, Actions 탭에서
수동 실행도 된다. 수동 실행 시 두 가지를 고를 수 있다.

- `demo` — 실제 시세 없이 데모 데이터로 배포 (첫 확인용)
- `refresh_bt` — 패턴 성적표 재계산 (패턴 로직을 고쳤을 때. 2~3분 추가)

**소스 점검이 실패하면 자동으로 데모 빌드로 넘어간다.** 데이터가 막힌 날
배포 전체가 실패해서 사이트가 죽는 것보다 낫다는 판단이다.

수집 전에 `tests/test_offline.py` 를 먼저 돌린다. 로직이 깨진 채로 데이터를
덮어쓰는 일이 없도록.

> 일봉 parquet을 매일 커밋하면 리포지토리가 계속 자란다. 500종목 기준
> 하루 수백 KB 수준이라 한동안은 문제없지만, 반년쯤 지나면
> `store.prune()`으로 오래된 구간을 잘라내거나 데이터 전용 브랜치로
> 분리하는 편이 낫다.

## 데이터 저작권

시세 데이터의 저작권은 각 제공처(KRX, 네이버 등)에 있다. 이 파이프라인은
데이터를 재배포하지 않고 **지표로 가공해 표시**하는 범위에서만 사용한다.
과도한 호출은 하지 않는다 (`config.SLEEP_BETWEEN_CALLS`).

## 실제 시세로 돌리기

코드는 전부 준비돼 있다. 남은 건 **네트워크가 열린 곳에서 한 번 돌리는 것**뿐이다.

```bash
pip install -r requirements.txt
python collect.py --probe          # ① 소스가 살아 있는지 30초 확인
python collect.py                  # ② 3년치 일봉 수집 (첫 실행 15~30분)
python scan.py --real --refresh-bt # ③ 스캔 + 성적표 (성적표 5~6분)
python build_app.py                # ④ public/ 빌드
python3 -m http.server 8000 --directory public
```

②까지 끝나면 `data/ohlcv/` 에 종목별 parquet이, `data/universe.parquet` 에
확정 유니버스가 생긴다. 이후 실행은 증분이라 훨씬 빠르다.

성적표(`--refresh-bt`)는 패턴 로직을 고쳤을 때만 다시 돌리면 된다.
평소에는 `python scan.py --real` 로 충분하다.

### 데모와 실제의 차이

`scan.json` 의 `is_demo` 플래그 하나로 앱 표시가 바뀐다.

| | 데모 | 실제 |
|---|---|---|
| 상단 띠 | 빨간 "샘플 데이터" 경고 | 회색 "YYYY-MM-DD 종가 기준" |
| 기준일 | 데이터에서 유도 | 데이터에서 유도 |
| 금리·환율 | `—` 로 비움 | FRED / ECOS (키 있을 때) |
| 뉴스 | 슬롯 설명만 | 언론사 RSS 제목 + 원문 링크 |
| 성적표 문구 | "샘플로 계산된 값" | "과거 성적이 미래를 보장하지 않습니다" |

**없는 것은 지어내지 않는다.** 뉴스나 지표를 못 받으면 그 영역이 화면에서
통째로 빠지거나 안내 문구로 바뀐다. 빈 자리를 그럴듯한 값으로 채우는 쪽이
훨씬 위험하기 때문이다.

### 정세 API 키 (선택)

없어도 앱은 돌아간다. 금리·환율 네 칸이 안 보일 뿐이다.

```bash
export FRED_API_KEY=...   # https://fred.stlouisfed.org/docs/api/api_key.html
export ECOS_API_KEY=...   # https://ecos.bok.or.kr/api/
```

GitHub Actions에서는 리포 Settings → Secrets에 같은 이름으로 넣으면 된다.

뉴스는 키가 필요 없다. 한국경제 RSS에서 **제목과 원문 링크만** 가져오고,
본문은 저장하지도 표시하지도 않는다. 탭하면 언론사 원문으로 넘어간다.

### D-day 일정

`data/calendar.json` 에 날짜를 적어두면 API 없이 D-day가 계산된다. 지난
일정은 자동으로 빠진다. 2026년 FOMC 일정은 넣어뒀고, 금통위(1·2·4·5·7·8·10·11월)와
미 CPI 발표일은 확정 날짜를 확인해 채워 넣으면 된다.

## 실시간 현재가 (선택)

패턴은 일봉으로 판정하니 실시간 시세가 들어와도 **결과가 바뀌지 않는다.**
이중바닥이든 삼각수렴이든 하루가 끝나야 확정되는 모양이라, 장중에 초 단위로
값이 들어와도 판정은 그대로다. 실시간이 바꾸는 건 **"지금 얼마인가" 하나**다.

그래서 이 앱은 무거운 계산은 하루 한 번 미리 해두고, 가격 숫자만 30초마다
갈아끼운다.

```
브라우저 ──30초──▶ 중계 서버 ──▶ KIS(국내) / Finnhub(미국)
```

중간에 서버가 필요한 이유는 두 가지다. 브라우저는 증권사 API를 직접 못 부르고
(CORS), API 키를 페이지에 넣으면 소스 보기로 새어 나간다.

### 붙이는 법

붙이는 방법이 둘이다. **내 PC 에서만 볼 거면 A 만 하면 된다.**

### A. 내 PC 에서만 — `실시간연결.bat` 더블클릭  ← 권장

`relay.py` 가 내 PC 안에서 도는 작은 중계기다. **가입할 계정도, 설치할 프로그램도
없다.** 파이썬 기본 기능만 쓴다.

1. `실시간연결.bat` 더블클릭
2. 한국투자증권 앱키·앱시크릿 붙여넣기 (미국은 Finnhub 키, 건너뛰어도 됨)
3. 그 자리에서 삼성전자 현재가를 실제로 받아와 보여준다 — 되는지 안 되는지를
   여기서 바로 안다
4. `실행하기` 더블클릭. 중계기는 같이 뜬다. 창을 하나 더 열 필요가 없다

키는 이 폴더의 `keys.json` 에만 저장되고 어디로도 전송되지 않는다.
`.gitignore` 에 들어 있다.

### B. 남에게도 보여줄 거면 — `worker/올리기.bat`

내 PC 가 꺼져 있어도 도는 주소가 필요할 때만. Cloudflare 계정과 Node.js 가
필요하다. 자세한 건 `worker/README.md`.

A 와 B 는 **응답 모양이 완전히 같다.** 앱은 어느 쪽에 붙었는지 모른다.

`config.py` 의 `LIVE_ENDPOINT` 를 비워 두면 폴링을 아예 하지 않는다. 지금까지처럼
종가 기준으로만 돈다.

### 앱이 하는 일

- **장중에만 부른다** — 국내 09:00~15:30, 미국 09:30~16:00. 시간대는
  브라우저가 계산하므로 서머타임도 알아서 맞는다.
- **보이는 종목만** — 화면에 실제로 떠 있는 것만, 시장당 최대 20개.
- **화면을 옮기면 즉시 한 번** — 목록에 들어와서 30초를 기다리지 않는다.
- **탭을 안 보면 쉰다** — 백그라운드에서는 폴링을 멈춘다.
- **못 받은 종목은 종가 그대로** — 지어내지 않는다.
- **지연 여부를 표시한다** — 상단에 `실시간 · 15:32:10` 또는 `지연 시세 · …`,
  실패하면 `갱신 실패 · 마지막 …`.

### 배포 전에 확인

증권사 키 없이도 앱 쪽 동작을 먼저 볼 수 있다.

```bash
python devtools/mock_quote.py 8792          # 중계 서버 흉내
# config.py 의 LIVE_ENDPOINT 를 http://localhost:8792 로
python scan.py && python build_app.py
python -m http.server 8000 --directory public
```
